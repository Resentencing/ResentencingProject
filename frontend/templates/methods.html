Data Sources

The dataset combines three types of records:

  1. CDCR tracking logs Case-level data: referral dates, outcomes, sentence reductions, and cost estimates. Updated monthly; this site shows the latest upload date.
  2. Court referral letters (PDFs) Narrative explanations from CDCR to sentencing courts: rehabilitation, programs, discipline, and why resentencing was recommended. Sent in batches, not on a fixed schedule.
  3. Race & ethnicity (PRA) Merged using CDC # or PID when those spreadsheets are released.

Document Processing and Data Extraction

Many source PDFs are scanned images, so we use optical character recognition (OCR) to make the text searchable.

  • Clean and standardize extracted text
  • Parse fields: demographics, institution, sentence, outcomes
  • Add researcher-coded variables from letter text (programs, employment, discipline-free time, etc.)

Data Integration and Variable Construction

Data from multiple sources are merged into a unified dataset. Administrative log variables provide the backbone of the dataset, while PRA-derived race and ethnicity variables are joined using unique identifiers. Letter-derived variables are incorporated through manual coding and automated text extraction processes. See the variable page for more information. A binary success variable is constructed to distinguish favorable outcomes (reduced or released) from all other outcomes.

Descriptive statistics are used to quantify total cases, success rates, sentence reductions, and cost savings. Aggregate measures include total and average years reduced and total and average fiscal savings.

Comparative analyses are conducted across geographic (county), institutional (facility), and demographic (race and ethnicity) categories. These analyses examine variation in referral volume, success rates, and outcome distributions.

Case Progression

A three-stage view represents the progression of cases through the resentencing process. Stage 1 includes all cases considered by CDCR. Stage 2 includes cases for which a referral letter was transmitted to the court. Stage 3 includes cases resulting in resentencing, defined as sentence reduction or release.

Visualization and User Interface

Data are presented through an interactive system that allows users to explore patterns through charts, search tools, and natural language queries. Visualizations are generated by aggregating case counts across selected variables and displaying them using bar charts and distribution plots. Stacked and grouped chart formats are used to compare outcomes across categories.

Query System and Retrieval-Augmented Generation

The system incorporates a natural language query interface that allows users to ask questions about the dataset. This interface uses retrieval-augmented generation (RAG), a method that combines database retrieval with language generation. When a user submits a query, the system retrieves relevant records from the dataset and uses those records to generate a response.

This approach ensures that generated responses are grounded in actual case data rather than relying solely on model-based inference. By retrieving and incorporating relevant records prior to response generation, the system reduces the likelihood of inaccurate or unsupported outputs and provides context-specific, evidence-based answers.

Software and Technical Implementation

The system is built using a combination of data processing, storage, and web-based tools that work together to transform legal records into a searchable and analyzable dataset.

Python and Flask are used to run the backend system. These tools process incoming data, handle search and query requests, manage uploads, and connect the different parts of the system. PythonAnywhere is used to host the backend and run the website in a live environment, including document processing and search functions.

Case data are stored using database systems including MySQL and Snowflake. MySQL is used for structured case-level records, extracted text, and metadata, while Snowflake is used to support larger-scale data storage and analysis. These systems allow the dataset to be organized, searched, and updated efficiently.

Document processing is performed using optical character recognition (OCR). OCR converts PDF letters into machine-readable text so that their contents can be searched, analyzed, and included in the dataset.

Data intake and automation are supported through Google Apps Script, Google Drive, and Google Sheets. These tools automate the process of receiving, organizing, and uploading documents into the system. Google Forms are used to manage access requests and user credentials, including automated workflows that send secure access links to approved users. Access and data use are governed by the project's Privacy Policy and Terms and Conditions.

The frontend website is hosted using Netlify, which provides a secure environment for delivering the user interface and connecting to backend services through serverless functions. Chart.js is used to create interactive charts and visualizations that allow users to explore patterns in the data. Earlier versions of the system used Matplotlib to generate static charts before transitioning to interactive visualizations.

Testing and quality control are supported by tools such as Playwright and Lighthouse, which are used to verify that the website functions correctly, loads efficiently, and meets accessibility standards.

Version control and deployment are managed through GitHub, which stores the codebase, tracks changes, and supports collaborative development and automated deployment workflows.

This project uses OpenAI tools, including ChatGPT, to help users ask questions and understand the data. The AI answers questions in plain language, summarizes information from case records, explains patterns across cases, and helps users understand the letters CDCR sends to courts. An API connects the website to the backend system and helps protect the system through controlled endpoints.
